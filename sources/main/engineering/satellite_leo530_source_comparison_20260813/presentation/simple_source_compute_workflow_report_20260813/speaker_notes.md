# 逐页讲稿

## 1. 从 38 km 气球到 530 km 近地轨道

这份简报只回答三个问题：气球和近地轨道的入射环境有什么不同，完整任务会带来多少额外计算维度，以及我们现在怎样组织计算、存储和数据处理。

## 2. 入射源：两类环境不是整体缩放

先看入射源本身。气球环境受残余大气层影响，轨道环境则要区分天区、地球反照、原初和次级粒子，所以不能把一套谱简单乘一个系数后当作另一套环境。图中不包含活化和延迟分量，也不是探测器计数谱。

## 3. 关键能带：并非全面更高或更低

正常轨道的宽带 gamma 在部分能区更低，但质子和正电子在一些能段更强。450–600 keV 的比值只是宽能带代理，不能替代窄 511 keV 线及探测器响应计算。因此，卫星环境不能简单概括成“更好”或“更差”。

## 4. 计算负担

如果只比较一个固定状态，气球和轨道的 prompt 输运可以按同一数量级规划。真正抬高轨道任务成本的是状态维度和完整物理链。建议先用代表状态试跑，测量每个 primary 的墙钟、内存和输出量，再确定完整轨道生产规模。

## 5. 当前计算方式

当前流程先冻结物理契约，再把大任务拆成短而可恢复的分片。分片规模根据实测耗时自适应调整，重尾粒子单独调度，每一片完成后立即验收，所以失败只需要补缺失的小片。

## 6. 存储与数据处理

原始层、验证层和分析层分开保存。原始产物继续留在 `runs/`，receipt 记录可审计证据，日常响应、筛选和任务折叠使用轻量派生输出，从而减少重复读取和重复解析。页面上的两个数据量对应不同层级，并不是删除或替代原始文件。

## 7. 早期与当前流程

当前流程的核心变化是短分片、即时验证、分层存储和严格分域。它缩小失败后的重算范围，也让后续响应和任务参数变化不必反复扫描全部原始文件。轨道版本的下一步，就是先做代表状态 pilot，再按实测成本扩展。
