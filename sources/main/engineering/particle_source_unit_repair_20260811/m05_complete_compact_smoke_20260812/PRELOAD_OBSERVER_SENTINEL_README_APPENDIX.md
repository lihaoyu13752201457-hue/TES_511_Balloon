# Installed no-preload / LD_PRELOAD observer sentinel appendix

Status: harness draft only. It is not a transport authorization, full-smoke
authorization, merge receipt, `M05_COMPLETE` claim, or N0 transport-speedup
claim. No authorization token is supplied or generated by this package.

## Default and exact shape

`code/run_preload_observer_sentinel.py` defaults to the read-only
`--print-plan` action. The plan is fail-closed against the current canonical
40-column `tape_contract.SIDECAR_COLUMNS`, source/spectrum authorities,
installed binaries, observer build, real MFileEventsSim consumer, schemas,
seed ledgers, and DSO closure. Plan construction writes nothing.

The authorized sentinel shape is fixed:

- 2 geometries x 7 families x 2 modes = 28 cells;
- four current shards per cell, using exactly rows 0, 1, and 2, all of which
  must already be pre-registered controls;
- one baseline and one preload invocation per shard;
- exactly two baseline/preload and two preload/baseline orders per cell;
- 112 matched pairs, 224 installed-Cosima invocations, and 672 transport
  events total.

Each pair uses one write-once derived three-row EventList and root sidecar, one
identical source card, one geometry, one command argv, and one transport seed.
The seed namespace is independent of registered production and current
full-smoke planning seeds. A later full smoke must not reuse a sentinel seed.

The source tape contains 20 hash-bound angular driver/spectrum definitions per
family/mode cell, but a three-row sentinel does not empirically cover all 20
bins. The 14 independently sampled family/mode Poisson clocks are not one
seven-family global accidental/live-time timeline.

## Execution authorization boundary

`--execute` requires an independently issued canonical, single-link,
write-once JSON token. The exact token shape is exposed by
`authorization_expected(plan_envelope)`. It binds at least the plan, harness,
installed Cosima, observer binary/build manifest, real MFileEventsSim consumer,
tape provenance manifest, planned-job manifest, output root, 672-event limit,
and 224-invocation limit. Any extra/missing key, altered hash/path/limit,
non-independent reviewer, or prior consumption fails before execution.

Before the first installed-Cosima child, the harness atomically creates an
exclusive sibling `.consumed.json` receipt. A failed or interrupted attempt
therefore cannot reuse its token. The harness never creates a token and never
updates `EXECUTION_STATUS.json` or another top-level authority.

The current active preflight is allowed to make `--print-plan` fail nonzero:
stale tape/runtime-projection hashes must be regenerated atomically by the
remediation owner. The sentinel harness must never relax canonical tape
validation to accommodate a stale preflight.

## Runtime and no-perturbation gates

Baseline explicitly omits `LD_PRELOAD` and `LD_AUDIT`. Preload adds only the
exact observer library, output/tape bindings, and the exact expected
`libCosima.so` path/SHA. Both arms otherwise inherit one hash-bound environment
allowlist plus fixed C locale, UTC, and one-thread settings.

Every process starts in a new process group. The supervisor enforces:

- 1 GiB aggregate new-byte hard cap and at least 20 GiB live reserve;
- 8 GiB process-group peak RSS;
- 2 GB `RLIMIT_FSIZE` and polled per-invocation output cap;
- 1800 seconds wall per process, with TERM then KILL of the whole process
  group after a 30-second grace period;
- preload peak RSS at most 64 MiB above its matched baseline;
- aggregate preload wall and OS CPU overhead no more than
  `max(60 seconds, 5 percent of baseline aggregate)`.

The pair must pass all of the following:

1. Installed Cosima exits zero without timeout, signal, or resource failure.
2. Runtime `/proc` maps bind installed Cosima/libCosima and show the observer
   only in the preload arm.
3. Both rich SIMs have Type SIM, Version 101, exact Geometry and Seed, one EN,
   exact TE/TS, three ordered SE/ID/TI events, exactly one INIT per event, and
   strict IA/HT/ED/EC/NS/PM/CC counts and event bytes.
4. After replacing exactly one `Date` header, the decompressed rich SIM bytes
   are identical. Zero or multiple Date records fail.
5. Each arm has exactly one native DAT. The raw DAT bytes and TT are identical;
   strict positive-TT/VN/RP/EN parsing passes, including valid zero-RP output.
6. The preload observer transaction passes the shared
   `preload_observer_validation.validate_observer_transaction` and an
   independent all-row recomputation. IDs, stable roots, particles, times,
   generated fields, normalized direction, and binary64 hashes join the exact
   three-row sidecar with no missing/duplicate row.
7. Each rich SIM passes the bound real installed MFileEventsSim consumer. This
   is a SIM parsing/consumer gate and does not substitute for full-smoke M05
   closure.
8. stderr is byte-identical; stdout is byte-identical after only a frozen set
   of parser-stage/run CPU timing lines is normalized. The observer emits no
   successful stdout/stderr output.

The observer build's static no-RNG scans remain mandatory. The runtime claim is
exact SIM/DAT outcome equality plus no-RNG code audit, not an unobserved
terminal RNG-state hash.

## Transaction authority

Inputs, arm receipts, pair receipts, runtime DSO closure, and the final
candidate commit use exclusive files, fsync, and atomic Linux
`renameat2(RENAME_NOREPLACE)` directory publication. Any failure leaves an
unmistakable non-authoritative partial tree and consumes the launch token.
The preload observer itself applies the same rule: if its stage-to-`.gpsobs`
rename succeeds but the parent fsync fails, it moves only the exact owned
published inode to a collision-safe `.gpsobs.failed*` name and exits nonzero;
the `atexit` finalizer is noexcept and never moves a foreign incumbent.

Only 112/112 pair PASS plus the final candidate commit is a sentinel PASS. A
second independent write-once token bound to that immutable candidate and the
unchanged installed closure is still required before full smoke.

Planning-only historical estimate: about 248.1 MiB plus under 0.6 MiB observer
data, about 51.6 seconds total BeamOn, roughly 50 minutes sequential wall time
or 15--25 minutes with four resource-safe workers. The draft harness currently
serializes transport for the clearest process-group/RSS authority; these are
planning point estimates rather than measured bounds.
